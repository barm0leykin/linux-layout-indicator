# PRD: Layout Indicator

**Версия:** 0.1 (Draft)
**Дата:** 2026-11-23
**Статус:** на ревью
**Рабочее название:** `layout-indicator`

---

## 1. TL;DR

Небольшая утилита, которая показывает всплывающий индикатор текущей раскладки клавиатуры **рядом с текстовым курсором** (или курсором мыши) в момент переключения языка. Дополнительно — показывает индикатор при **фокусе на поле ввода**.

Целевая среда сейчас: Ubuntu 22.04 + KDE Plasma 5.24 + X11, раскладки `us,ru`, переключение `Alt+Shift`.
Стратегическая цель: любая Linux-система, по возможности Windows и macOS.

Размер: утилита-демон, < 100 МБ RAM, нулевая нагрузка в простое.

---

## 2. Проблема

### 2.1 Контекст

Пользователь постоянно переключается между `us` и `ru` (`Alt+Shift`). В момент переключения нет визуальной обратной связи **там, куда смотрит пользователь** — в точке ввода текста.

### 2.2 Что есть сейчас

| Механизм | Где | Почему не решает |
|---|---|---|
| Апплет «Keyboard Layout» в системном трее KDE | правый нижний угол экрана | взгляд при наборе — в центре экрана у каретки; трей нужно специально искать глазами |
| LED Scroll Lock (`grp_led:scroll`) | корпус клавиатуры | нет LED на ноутбуках/компактных клавиатурах; не видно при взгляде в экран |
| Ничего | — | — |

Факт: в текущей конфигурации включены оба костыля — `grp:alt_shift_toggle` и `grp_led:scroll` (см. §14.1). То есть пользователь уже пытался решить проблему доступными средствами и не смог.

### 2.3 Последствия

- Набор текста «не в той раскладке»: `ghbdtn` вместо `привет`, `ltpyf` вместо `лезна`.
- Пользователь замечает ошибку **после** набора нескольких слов → переключение, стирание, перенабор.
- Постоянный фоновый контроль состояния («а какая сейчас раскладка?») — когнитивная нагрузка.
- Отдельная боль: **потеря раскладки при смене окна** — вернулся в терминал из браузера, а там другой язык.

### 2.4 Формулировка проблемы

> При переключении раскладки пользователь не получает мгновенной визуальной обратной связи в точке ввода текста, из-за чего набирает текст в неверной раскладке и тратит время на исправление.

## 3. Цели и не-цели

### 3.1 Цели (Goals)

| # | Цель | Измеримость |
|---|---|---|
| G1 | Мгновенная визуальная обратная связь при смене раскладки рядом с точкой ввода | p95 задержки «событие → пиксель» < 50 мс |
| G2 | Индикатор не мешает работе | не крадёт фокус, клики проходят сквозь, не появляется в списке окон и на панели задач |
| G3 | Работает на текущей системе без привилегий | X11 + Plasma 5.24, без root, без перехвата клавиатуры |
| G4 | Минимальный footprint | простой: 0 % CPU, < 100 МБ RAM; старт < 300 мс |
| G5 | Архитектура допускает другие платформы | ядро отделено от платформенных бэкендов |
| G6 | Приватность by design | нет сети, нет логирования нажатий, открытый код |

### 3.2 Не-цели (Non-goals)

- **Не** менять раскладку и не быть менеджером раскладок.
- **Не** заменять input method (fcitx5/ibus) и не встраиваться в цепочку ввода.
- **Не** реализовывать «свою раскладку на каждое окно» (per-window layout) — отдельная задача, см. §15.
- **Не** показывать CapsLock/NumLock (другая проблема, другой инструмент).
- **Не** быть кроссплатформенным «с первого дня» — только архитектурная готовность.
- **Не** собирать телеметрию, не требовать аккаунтов, не ходить в сеть.
- **Не** работать в Wayland на первом этапе (см. §7.4 и риск R1).

## 4. Пользователи и сценарии

### 4.1 Персона

Разработчик/DevOps, Linux (Ubuntu + KDE), двуязычный набор (`ru`/`en`), часто работает в терминале, редакторе кода, мессенджерах, браузере. Клавиатура без LED-индикаторов или LED не виден.

### 4.2 Сценарии

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| S1 | Пользователь нажимает `Alt+Shift` в редакторе кода | рядом с кареткой появляется «RU»/«EN», держится ~0.7 с и плавно исчезает |
| S2 | `Alt+Shift` в терминале | то же; если каретка недоступна — у курсора мыши |
| S3 | Быстрое переключение туда-обратно (`Alt+Shift` ×2) | индикатор не мигает/не дёргается, содержимое меняется на месте, таймер удержания продлевается |
| S4 | Переключение при полноэкранном видео/игре | индикатор **не** показывается (настраиваемо) |
| S5 | Фокус в поле ввода другого приложения | (M2) кратко показывается текущая раскладка — «какой язык здесь включён» |
| S6 | Работа в двух мониторах | индикатор появляется на том мониторе, где каретка/мышь |
| S7 | Первый запуск | утилита стартует в трее, показывает короткую подсказку, ничего не ломает |
| S8 | Индикатор висит поверх нужного места | можно кликнуть «сквозь» него; он не перехватывает мышь и не забирает фокус |

## 5. Функциональные требования

Приоритеты: **M** = Must (M1), **S** = Should (M2), **C** = Could (later), **W** = Won't (v1).

### FR-1. Обнаружение смены раскладки — **M**

- FR-1.1 Событийное получение смены XKB-группы (X11). Без поллинга в основном режиме.
- FR-1.2 Не перехватывать клавиатуру (никаких `XGrabKey` на `Alt+Shift`, никаких низкоуровневых хуков) — утилита не должна влиять на ввод.
- FR-1.3 Работать независимо от фокуса и активного приложения.
- FR-1.4 Определять соответствие «индекс группы → код раскладки» (`0 → EN`, `1 → RU`) из конфигурации XKB, с поддержкой 3+ раскладок.
- FR-1.5 Fallback-режим поллинга (напр. 150 мс), если события недоступны (нестандартный сервер, XDMCP, проброс).
- FR-1.6 Реагировать на смену конфигурации раскладок на лету (пользователь добавил `de` в настройках) без перезапуска.

### FR-2. Показ индикатора при переключении — **M**

- FR-2.1 Показывать индикатор при любом изменении группы, включая переключение не только хоткеем, но и кликом по апплету трея.
- FR-2.2 Автоскрытие по таймеру (см. §6.3).
- FR-2.3 Не показывать при старте утилиты и при первичной инициализации.
- FR-2.4 Настраиваемое подавление (см. FR-8.3).

### FR-3. Позиционирование — **M**

- FR-3.1 Режим «у курсора мыши» — базовый, работает всегда и везде.
- FR-3.2 Режим «у текстовой каретки» — **S** (M2), через AT-SPI2; при неудаче — автоматический откат к FR-3.1.
- FR-3.3 Режим «у активного окна» — **C** (дешёвый и надёжный компромисс: правый верхний угол активного окна).
- FR-3.4 Учёт границ экрана и выбор стратегии «куда встать» (см. §6.4).
- FR-3.5 Мультимонитор: позиция на мониторе, содержащем точку привязки.
- FR-3.6 HiDPI / масштабирование: размеры и отступы в логических пикселях.

### FR-4. Индикатор при фокусе на поле ввода — **S**

- FR-4.1 При получении фокуса редактируемым элементом показывать текущую раскладку.
- FR-4.2 Не срабатывать на фокус окна без текстового поля.
- FR-4.3 Не срабатывать при переключении между полями одного окна чаще, чем раз в N секунд (антишум).
- FR-4.4 Опционально (по умолчанию **выключено**): атрибут «раскладка этого окна», если в будущем появится per-window layout.

### FR-5. Внешний вид — **M**

- FR-5.1 Компактный бейдж: две заглавные буквы кода раскладки (`EN`, `RU`, `DE`).
- FR-5.2 Тёмная и светлая тема; по умолчанию — следовать системной.
- FR-5.3 Контрастность, достаточная для чтения на любом фоне (обводка/тень/подложка).
- FR-5.4 Опционально: пользовательская тема/иконки — **C**.
- FR-5.5 Без флагов по умолчанию (флаг ≠ язык; RU/EN-флаги спорны и путают). Флаги — только как опциональный пакет иконок.

### FR-6. Настройки — **S**

- FR-6.1 Файл конфигурации (YAML) в `~/.config/layout-indicator/config.yaml`.
- FR-6.2 Параметры: режим позиционирования, тайминги, тема, смещения, подавление в fullscreen, включение focus-триггера, выбор монитора.
- FR-6.3 Горячая перезагрузка конфига (SIGHUP или watch файла).
- FR-6.4 GUI настроек — **W** (v1: только файл + флаги CLI).

### FR-7. Интеграция с системой — **S**

- FR-7.1 Автозапуск в сессии KDE (`.desktop` в `~/.config/autostart`).
- FR-7.2 Иконка в системном трее с быстрым вкл/выкл — **C**.
- FR-7.3 Корректная работа как демон: один экземпляр (lock-файл / D-Bus name).
- FR-7.4 Логи через journald/syslog, уровень настраиваем.

### FR-8. Не мешать — **M**

- FR-8.1 Не перехватывать ввод (мышь/клавиатуру).
- FR-8.2 Не забирать фокус.
- FR-8.3 Не показываться, если активное окно — полноэкранное (видео, игра, презентация); настраиваемо.
- FR-8.4 Не появляться в списке окон (`Alt+Tab`), на панели задач, в переключателе.
- FR-8.5 Не ломать работу других приложений при своём падении (изолированный процесс, не in-process хук).

### FR-9. Диагностика — **S**

- FR-9.1 Команда `--doctor`: печатает окружение (X11/Wayland, DE, список раскладок, доступность AT-SPI), результат проверок.
- FR-9.2 `--dry-run`/`--debug`: печатает события смены группы без показа оверлея.
- FR-9.3 Понятные сообщения об ошибках (нет дисплея, нет композитора, AT-SPI выключен).

### FR-10. Явно вне объёма — **W**

- Смена раскладки, per-window layout, IM, CapsLock/NumLock, синхронизация настроек в облако, телеметрия, автоперевод «исправь раскладку» (перепечатывание текста в правильной раскладке — интересно, но отдельный продукт).

## 6. UX-спецификация индикатора

### 6.1 Внешний вид

```
        ┌──────┐
   текстовый курсор│ EN │
        └──────┘
```

| Параметр | Значение (1x) |
|---|---|
| Форма | скруглённый прямоугольник, радиус 6–8 px |
| Размер | ~44 × 30 px (две заглавные буквы, шрифт 13–14 px semi-bold) |
| Отступы | 8 px по горизонтали, 4 px по вертикали |
| Фон | тёмная тема: `#1b1c1d` @ 92 %; светлая: `#ffffff` @ 95 % |
| Текст | тёмная тема: `#ffffff`; светлая: `#1b1c1d` |
| Обводка | 1 px, полупрозрачная, контрастная к фону |
| Тень | мягкая, 8–12 px размытия (если композитор позволяет) |
| Смещение от привязки | +14 px по X, −24 px по Y (справа-сверху от каретки) |

Коды раскладок: двухбуквенные, верхний регистр (`EN`, `RU`, `DE`, `UK`). Соответствие «группа → код» берётся из XKB-конфигурации.

### 6.2 Состояния

| Состояние | Условие | Визуал |
|---|---|---|
| hidden | нет активности | окно скрыто, процесс спит |
| fade-in | смена раскладки | прозрачность 0 → 92 % за 120 мс |
| hold | сразу после fade-in | виден 700 мс |
| fade-out | таймер истёк | прозрачность → 0 за 200 мс |
| switching | повторное переключение во время показа | содержимое меняется на месте (кросс-фейд текста 100 мс), таймер hold сбрасывается; **окно не перемещается** |

**Важно:** при быстром переключении окно не должно прыгать по экрану — позиция фиксируется в момент первого показа и обновляется только после полного скрытия.

### 6.3 Тайминги

| Параметр | Значение | Настраиваемо |
|---|---|---|
| fade-in | 120 мс | да |
| hold | 700 мс | да (300–5000) |
| fade-out | 200 мс | да |
| полный цикл | ~1.0 с | — |
| кросс-фейд при смене | 100 мс | нет |

Быстрое переключение: каждое новое событие продлевает hold с текущего момента.

### 6.4 Позиционирование и края экрана

1. Точка привязки: каретка (если доступна) → иначе курсор мыши → иначе центр/угол активного окна.
2. Предпочтительная позиция: справа-сверху от привязки.
3. Если не влезает справа — слева. Если не влезает сверху — снизу. Если не влезает никуда — по центру привязки с ограничением по краям.
4. Минимальный зазор до края экрана/рабочей области: 8 px.
5. Рабочая область — без учёта панелей KDE (`_NET_WORKAREA`/struts), чтобы индикатор не прятался под панелью.

### 6.5 Особые случаи

| Случай | Поведение |
|---|---|
| Полноэкранное окно активно | не показывать (FR-8.3) |
| Нет композитора (X11 без compositing) | непрозрачная подложка, без тени, без прозрачности |
| Каретка за пределами экрана / координаты мусорные | откат к курсору мыши |
| Переключение апплетом трея (не хоткеем) | показывать так же |
| 3+ раскладок | показывать код нужной группы |
| Изменение раскладки другим приложением/скриптом | показывать так же (единый источник — XKB state) |
| Смена монитора во время показа | доиграть на исходном, новый показ — на новом |

## 7. Техническая архитектура

### 7.1 Общая схема

```
                 ┌──────────────────────────────────────────┐
                 │            layout-indicator              │
                 │                                          │
  X server ─────►│  Backend (platform-specific)             │
  (или         ◄─┤   • X11: XkbStateNotify + XQueryPointer    │
   композитор)   │   • KWin Wayland: KWin effect (позже)     │
                 │   • Windows: WM_INPUTLANGCHANGE            │
                 │   • macOS: TISInputSource                  │
                 │            │ LayoutChanged{group}         │
                 │            ▼                             │
                 │  ┌──────────────────────┐                │
  AT-SPI2 ──────►│  │  PositionResolver    │                │
  (опц.)         │  │  caret → pointer →   │                │
                 │  │  window              │                │
                 │  └──────────┬───────────┘                │
                 │             ▼                            │
                 │  ┌──────────────────────┐                │
                 │  │  Overlay renderer    │  ─────────────►│ X11 ARGB
                 │  │  (fade/hold/theme)   │                 │ override-redirect
                 │  └──────────────────────┘                 │
                 │             ▲                            │
                 │        Config (YAML)                     │
                 └──────────────────────────────────────────┘
```

Три слабо связанных слоя:

1. **Backend** — «откуда узнать про смену раскладки и где точка привязки». Платформенно-зависимый, заменяемый.
2. **Presenter** — политика показа (тайминги, подавление, дедупликация).
3. **Renderer** — как нарисовать поверх других окон, не мешая им.

### 7.2 X11 backend (текущая цель)

| Задача | Механизм | Комментарий |
|---|---|---|
| Смена раскладки | `XkbSelectEventDetails(XkbStateNotify, XkbGroupStateMask)` | событийно, без перехвата key, без root |
| Текущая группа | поле `group` из события `XkbStateNotify` | 0..3 |
| Список раскладок | `setxkbmap -query` на старте + перечитывание при изменении конфигурации | даёт `layout: us,ru` в нужном порядке |
| Курсор мыши | `XQueryPointer` (по запросу, не поллинг) | мгновенно |
| Активное окно | `_NET_ACTIVE_WINDOW` + `_NET_WM_WINDOW_TYPE` | для режима FR-3.3 и подавления fullscreen |
| Рабочая область | `_NET_WORKAREA` / struts | зазор до краёв |
| Каретка | AT-SPI2 (`AtspiText.get_character_extents`) — опционально | нестабильно, отключаемо |
| Отрисовка | X11 ARGB visual + `override_redirect`, пустая input-shape | клики сквозь; окно не управляется WM |
| Прозрачность | композитор (KWin) | без него — непрозрачный fallback |

**Запрещённые подходы (сознательно):**
- `XGrabKey` / глобальные хуки на `Alt+Shift` — влияет на ввод, конфликтует с другими приложениями.
- Опрос `XkbGetState` в цикле как основной механизм — лишние wakeup'ы.
- `exec` внешних утилит (`xdotool`) на каждое событие — задержка и зависимость от окружения.

### 7.3 Позиционирование каретки (tiered)

| Уровень | Метод | Точность | Надёжность | Стоимость |
|---|---|---|---|---|
| T0 | курсор мыши | «рядом» | 100 % | бесплатно |
| T1 | угол активного окна | приблизительно | 100 % | дёшево |
| T2 | AT-SPI2 caret extents | точно | зависит от приложения | дорого (a11y-события) |
| T3 | input-method `cursor_rect` (fcitx5/ibus) | точно | только для IM-приложений | внедрение в IM-стек — **не делать** |

Рекомендация: **T0 по умолчанию**, T2 — опция (M2), T1 — как компромисс, T3 — не реализовывать (слишком инвазивно).

Ожидаемая надёжность T2: GTK/Qt-приложения с включённым a11y — хорошо; Electron/Chromium — частично; терминалы — обычно нет. Всегда должен быть автоматический откат.

### 7.4 Другие платформы (архитектурная готовность)

| Платформа | Детект раскладки | Каретка | Оверлей | Сложность |
|---|---|---|---|---|
| **X11 (сейчас)** | XkbStateNotify | AT-SPI2 | override-redirect ARGB | **низкая** |
| **KDE Wayland** | код внутри KWin (effect/скрипт) | AT-SPI2 (ограниченно), иначе мышь | рисует KWin effect | **высокая** |
| GNOME Wayland | GNOME Shell extension | extension + AT-SPI | extension | высокая |
| Windows | `WM_INPUTLANGCHANGE` / `GetKeyboardLayout` | `GetGUIThreadInfo` → `rcCaret` | layered, no-activate, click-through окно | средняя |
| macOS | `TISInputSource` + `kTISNotifySelectedKeyboardInputSourceChanged` | `AXUIElement` + `kAXBoundsForRange` | non-activating `NSPanel`, `ignoresMouseEvents` | средняя |

**Ключевой архитектурный вывод:** в Wayland модель безопасности **намеренно** лишает сторонние приложения глобального наблюдения за вводом и произвольного позиционирования окон. Единый бинарник, «работающий везде на Linux», невозможен — для Wayland нужен код, исполняемый **внутри композитора** (KWin effect / GNOME extension). Отсюда требование G5: ядро + сменные бэкенды.

Парадокс, который стоит зафиксировать: **Windows и macOS для этой задачи проще, чем Wayland-Linux** — там нужные API официальные и стабильные.

### 7.5 Предлагаемый стек

| Вариант | Плюсы | Минусы | Оценка |
|---|---|---|---|
| **Rust** (`x11rb`, `fontdue`/`cosmic-text`, `serde`, `notify`) | один статический бинарник, низкая память, быстрый старт, безопасная работа с X11-протоколом | нужно вручную собирать ARGB-окно; текстовый рендер без тулкита | **рекомендуется** |

## 9. Приватность и безопасность

Утилита по природе своей **наблюдает за вводом** (смену раскладки) и, в режиме T2, **читает геометрию текста в чужих окнах**. Это «keylogger-adjacent» возможность, и с ней надо обращаться соответствующе.

Обязательства:

- **Нет сети.** Никаких HTTP/DNS-запросов. Проверяется в коде и в release-чеклисте.
- **Нет логирования нажатий.** В отладочном режиме — только `group` и координаты, никогда не символы, не содержимое полей, не заголовки окон.
- **Нет чтения содержимого полей.** AT-SPI используется только для `caret offset` + `character extents`.
- **Минимум привилегий.** Никаких root/setuid. KWin-плагин (если появится) устанавливается явно и с предупреждением о правах.
- **Прозрачность.** README с разделом «что утилита видит и чего не видит»; открытый исходный код.
- **Отключаемость.** Всё, что читает a11y, выключено по умолчанию.

## 14. Зафиксированное окружение

### 14.1 Текущая система (замерено 2026-11-23)

| Параметр | Значение |
|---|---|
| Display server | **X11** (`XDG_SESSION_TYPE=x11`) |
| Desktop | **KDE Plasma 5.24.7** (`plasmashell 5.24.7`, `kwin_x11 5.24.7`) |
| Дистрибутив (по версиям) | Ubuntu 22.04 (`g++ 11.4.0`, `python 3.10.12`, `cmake 3.22.1`) |
| Раскладки | `layout: us,ru` |
| Переключение | `grp:alt_shift_toggle` |
| Индикатор раскладки | `grp_led:scroll` (LED Scroll Lock) — костыль |
| Input method | нет (`XMODIFIERS=@im=none`, `GTK_IM_MODULE=xim`, `QT_IM_MODULE=xim`) |
| AT-SPI2 | **шина отвечает**, `pyatspi`/`pygobject` доступны |
| Тулчейн | `cargo`/`rustc` есть; `python-xlib 0.29`; **Qt dev-пакетов нет**; `xdotool`, `xprop`, `setxkbmap`, `gdbus` есть |

### 14.2 Что это значит для реализации

1. Раскладка — **чистый XKB**, IM не участвует → backend должен работать с XKB-группами, а не с IM. (Но заложить IM-адаптер на будущее — разумно.)
2. `XkbStateNotify` — основной механизм; проверяется в M0 за минуты.
3. AT-SPI доступен → T2 реализуем, но требует проверки по приложениям.
4. Qt-стек сейчас «из коробки» недоступен (нет dev-заголовков) → Rust или Python выглядят практичнее.

## 16. Глоссарий

| Термин | Значение |
|---|---|
| **XKB group** | группа раскладки в X11 (0 — первая в списке, 1 — вторая и т.д.) |
| **XkbStateNotify** | X11-событие изменения состояния клавиатуры, в т.ч. смены группы |
| **Каретка (caret)** | текстовый курсор внутри поля ввода (не путать с указателем мыши) |
| **AT-SPI2** | шина доступности Linux (D-Bus), через неё можно узнать позицию каретки |
| **override-redirect** | X11-окно, которым не управляет оконный менеджер (нет рамки, нет в списке окон) |
| **input shape** | X11-область окна, принимающая ввод; пустая = клики проходят сквозь |
| **override / layer-shell** | Wayland-протокол для оверлеев (`wlr-layer-shell`), поддержан KWin |
| **IM** | input method (fcitx5, ibus) |
